# Decisions

Each ambiguity in the MVP brief, the option chosen, and why. Newest last.

| # | Topic | Decision | Why |
|---|---|---|---|
| 1 | "Seven monthly series" | Treat each series at its real frequency (quarterly, monthly, daily, hourly). Date-range buttons go on the dated series; the undated BurstGPT series get count-based ranges. | The data is not monthly; resampling would invent numbers. |
| 2 | Folder structure | Pages move to `app_pages/`, shared UI to `ui/`, logic to `core/`; file names (and so URLs) stay the same. | Matches the brief; URLs and behaviour unchanged. |
| 3 | Where heavy statistics run | Diagnostics, cross-validation and calibrated intervals are computed offline by `src/build_artifacts.py` into `artifacts/`, then only read by the app. | Render's free tier has about 0.1 CPU and sleeps; nothing slow may run on a page load. |
| 4 | Download label | The chart download button says "Download these numbers" (file is .csv). | The plain-language check bans "CSV" on screen. |
| 5 | Range controls on undated series | BurstGPT charts get "Last 7 days / Last 30 days / All" (hours: "Last day / Last week / All") instead of 6M/1Y/5Y. | Their x axis counts days or hours, not dates. |
| 6 | Shock markers | COVID-19 (Mar 2020) and ChatGPT launch (Nov 2022) are marked on dated charts that span them (pay levels, hosting prices). | Only these two are documented shocks relevant to the series. |
| 7 | 3D | The cost donut opens flat; 3D is one click away. The year-end 3D columns stay inside a closed panel. | "Flat charts by default (3D optional)". |
| 8 | Theme | `.streamlit/config.toml` has `[theme.light]` and `[theme.dark]`; the app's own switch still drives the page styles and follows the visitor's setting on the first visit. | Native theme first, custom styles kept for the look. |
| 9 | One view state | `core/state.py` holds company, outlook, caution and trend in the session and mirrors them to the address (`?preset=small&outlook=optimistic&caution=more&trend=pay`). Widgets keep their own keys and write back on change. | Streamlit forgets a widget's value on pages that do not draw it; a separate key survives page changes. |
| 10 | Company presets | Small team (50 people) and Enterprise (5,000) scale the example company's head count, build hours, hosting, enablement and ramp. They are run through the same engine once per server and cached; nothing is saved to disk. | Render's disk is wiped on restart; the free CPU is small, so each preset runs once. |
| 11 | Trend picker | Three groups (Pay, Technology, AI usage), then the trend inside the group. The choice is shared by the three Forecast pages. | Seven flat pills were hard to scan on a phone. |
| 12 | First-visit tour | A three-step dialog on Welcome, once per browser (cookie `aiwi_tour=seen`, no personal data); off with `?tour=off`. | Short and skippable; the cookie avoids showing it on every visit. |
| 13 | Error boundary | A failing page shows a plain warning and logs the traceback to the server log; the rest of the site keeps working. Tests set `AIWI_STRICT=1` so errors still fail them. | Visitors never see a traceback; bugs are not hidden from tests. |
| 14 | Partial reruns | The overview view switch, the reliability "show all" switch and the donut flat/3D switch redraw only their own section (`st.fragment`). | Less waiting on the small server. |
| 15 | Calibrated ranges | The likely range on the Forecast pages and the Welcome chart is now a split-conformal range: fold k is calibrated only on folds before it (at least 3), score = abs(error) / (abs(forecast) × sqrt(step)). A darker 50% band sits inside the 80% band. The expected line is unchanged. | The old ranges held 29% of real values for two AI usage series in rolling-origin CV; the brief asks for 70–90%. All seven are now 71–86%. |
| 16 | Range beyond the checked horizon | Width grows with sqrt(step) only up to the furthest step the cross-validation scored (e.g. 24 hours for hourly requests) and stays flat beyond; series that cannot go below zero are floored at zero. | No unchecked extrapolation; no negative counts. |
| 17 | Analyst mode | One switch in the side panel (off by default, `?analyst=on` in the address). It adds sections to The data we used (STL, ADF/KPSS verdict, ACF/PACF, subseries, CUSUM break test, outliers) and How reliable it is (model cards, CV table with DM test, error by step, residuals with Ljung–Box and Q–Q, coverage plot and interval score). Technical names are allowed only there, each with a plain explanation. | Keeps the plain-English default for everyone else. |
| 18 | Precomputed analysis | `src/build_artifacts.py` writes everything Analyst mode needs to `artifacts/` (committed, about 0.5 MB). Nothing is fitted on a page load. Theta is refitted at the same fold origins; Prophet/LightGBM are not added. | Render's free tier has about 0.1 CPU; extra dependencies were not worth it. |
| 19 | Input uncertainty | Time saved (×0.5–1.6), realisation rate (×0.7–1.3), adoption level (×0.75–1.15) and training hours (×0.75–1.5) vary per draw, PERT around the entered value (`config_phase4.INPUT_SPREAD`), drawn after the forecast paths. Ranges are judgement calls, applied to any company's figures. | Payback was a flat 0% / 100% because only the forecast paths varied. Multipliers keep it working for presets and visitors' own figures. |
| 20 | Decision figures | NPV at 10% a year of the typical monthly balance changes; return on cost = typical end balance ÷ typical total cost; cost per person-month = typical total cost ÷ active-user months. Shown on When it pays for itself, in the Excel file and the PDF memo. | Simple, explainable, from the saved results. |
| 21 | Goal-seek | One question: what time saved gives an even chance of paying back within the horizon (bisection, 1,000 draws a step, cached per figures). Shown on What matters most and in the memo. | Time saved is the most uncertain and most influential input. |
| 22 | Scenario compare and save | Compare: the three outlooks side by side (table, Excel, memo), and the address bar reproduces a view. Save/load: a small JSON scenario file kept on the visitor's computer, validated on load (fields known, numbers ≥ 0). Uploads limited to 1 MB. | No server storage (Render's disk is wiped). |
| 23 | Downloads | PDF gains a decision-memo first page; Excel (openpyxl 3.1.5, pinned) has the decision summary, month-by-month table and figures used. | Brief asks for a memo and XLSX; openpyxl is small and pure Python. |
| 24 | Provenance | Each of the seven trends has a closed "Where this data comes from" panel (source, publisher, dataset or series ID, link, licence, how often, what it covers, what we did) on The data we used and How we forecast. Licences checked at the source on 25 Nov 2026: BurstGPT CC BY 4.0 (GitHub), WildChat-1M ODC-BY (Hugging Face), FRED/BLS series "Public Domain: Citation Requested". These panels may name sources (proper nouns); the banned-word test skips them like the technical-details panel. | Trust needs named, linkable sources; source names cannot be paraphrased. |
| 25 | Methodology page | "How we forecast" is added at the end of the Forecasts group (after How reliable it is), with steps, limits, sources and how to repeat it. The nine existing pages keep their order and addresses; the Next chain now passes through it. | The brief asks for a methodology page; this is the least disruptive place. |
